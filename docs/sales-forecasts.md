# Прогноз продаж

Блок хранит управляемые версии прогноза по товару, клиенту, складу и неделе или месяцу. Первый контур предназначен для ручного ввода и импорта; автоматические методы расчёта будут добавлены после согласования полной модели расчётов.

## Жизненный цикл

1. Сотрудник создаёт черновик и добавляет строки с базовым количеством и промо-приростом.
2. Черновик отправляется на коммерческую проверку.
3. Коммерческий директор принимает прогноз или возвращает его с комментарием.
4. Директор или исполнительный директор утверждает проверенную версию.
5. Утверждённая версия не редактируется. Для изменений создаётся новая версия с `based_on_id`; строки копируются в новый черновик.

В один момент для одинакового названия, сценария и горизонта может быть утверждена только одна версия. При утверждении следующей предыдущая получает статус `superseded`.

## Права

- `forecasts.view` — список и статусы версий;
- `forecasts.detail` — строки прогноза;
- `forecasts.create`, `forecasts.update` — создание и изменение черновика;
- `forecasts.review` — коммерческая проверка;
- `forecasts.approve` — итоговое утверждение;
- `forecasts.archive` — архивирование неутверждённых или заменённых версий.

Запись в таблицы напрямую закрыта. Все изменения выполняются через RPC миграции `202609273000_sales_forecasts.sql` и попадают в журнал действий.
