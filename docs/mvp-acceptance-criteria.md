# Критерии приёмки MVP: пилот RVI / Fazer

Статус документа: черновик. Критерии проверяют первый рабочий пилот — фазы 0–4 из [`mvp-implementation-plan.md`](./mvp-implementation-plan.md). Каждый критерий записан как сценарий «Дано / Когда / Тогда», чтобы его можно было превратить в автоматический или ручной тест.

Термины — [`data-model.md`](./data-model.md#0-термины); права — [`roles-permissions.md`](./roles-permissions.md); процесс — [`process-rvi.md`](./process-rvi.md).

## Условия проверки

- **Тестовые данные вымышленные.** Реальные договоры, реквизиты, персональные данные, цены и коды маркировки не используются.
- **Пользователи.** Для каждой роли — отдельный тестовый пользователь: `director`, `executive_director`, `commercial_director`, `logistics_director`, `senior_logistics_manager`, `logistics_specialist`, `accountant`, `marketer`, `administrator`. Дополнительно: отключённый пользователь; пользователь с двумя ролями.
- **Справочники.** Тестовый производитель (Финляндия); тестовый клиент (Казахстан) с требованием к ОСГ 60%; склады AKT, AST, ALA, IN_TRANSIT; маршрут «Финляндия → Казахстан»; товары «Тестовый товар А» (нужен стикер) и «Тестовый товар Б».
- **Параметры, которые ещё не утверждены ARSEO** (формула ОСГ, запас на брак, минимальный тираж, согласующие), задаются в тесте явно. Результат проверяется относительно этих параметров. Если ARSEO утвердит другие значения, меняются параметры, а не сценарий.
- **Проверки прав** выполняются дважды: через интерфейс и прямым запросом к Supabase с ключом пользователя (проверка RLS).

## Сквозной сценарий пилота

Приёмка MVP считается пройденной, если на тестовых данных без ошибок выполнен сквозной сценарий и все критерии выше:

1. Администратор создаёт пользователей и назначает роли (AC-AUTH, AC-ROLE).
2. Заводятся производитель, клиент, товары А и Б, в том числе импортом (AC-DATA).
3. СМЛ создаёт поставку с кодом проекта, заказ согласуется (AC-SHIP).
4. Этапы 4–6 идут параллельно; создаются две перевозки (AC-STAGE).
5. Загружаются и проверяются инвойс, упаковочные листы и CMR, одна версия исправляется (AC-DOC).
6. Две перевозки прибывают в разные дни; приёмка, пересчёт с расхождением, партии (AC-RECV, AC-BATCH).
7. Макет стикера согласуется со второй попытки, стикеры рассчитываются, заказываются и наносятся (AC-STICK).
8. Маркировка получает статус «Не требуется» по условию (AC-STAGE-07).
9. Клиентский заказ подбирает партии по FEFO; для партии с низким ОСГ оформляется гарантийное письмо (AC-FEFO).
10. Отчёт по поставке совпадает с движениями; вся история видна в журнале; уведомления доставлены (AC-REPORT, AC-AUDIT, AC-NOTIF).
