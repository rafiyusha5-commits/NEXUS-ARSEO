Счётчики вызовов в action-тестах **не равны** проверке количества строк настоящей БД.
SQL fixtures не проверяют доступность физических объектов Storage. PGlite не проверяет
конкурентные PostgreSQL-сессии. Компонентный браузерный тест не доказывает безопасное
возобновление через авторизованный интерфейс полного приложения.

## Воспроизведённое несоответствие интерфейса

`processingState` возвращал `failed` для всех временных сбоев. Новый тест сначала упал
с `failed != waiting_retry`. Минимальное исправление только отображает временные
SOURCE_UNAVAILABLE/STORAGE_FAILED/INTERRUPTED как «Ожидает повторения»; неопределённый
исход, доступ, сессия и изменённый источник требуют действия сотрудника.
Подпись явно говорит, что автоматический повтор **не запущен**. Сохранённые состояния
БД, права, lease и ручные подтверждения не изменяются. Проценты не добавлены.

а предыдущий GitHub CI отклонён до запуска из-за оплаты/лимита аккаунта. Не менять
платёжные настройки самостоятельно. Нужна доступная одноразовая инфраструктура для
полного сценария с настоящими Auth/PostgREST/Storage и управляемой HTTP-подменой Drive/OCR.
До прохождения всех девяти сценариев PR должен оставаться черновиком.

Миграций нет. Общие точки пересечения: `processing-status`, тест action импорта,
существующий OCR SQL-тест и браузерный runner статусов. Применять только к согласованной
основе после проверки владельцем; main не изменять.
