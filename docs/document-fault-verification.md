## Точки сбоя

| Сценарий | Ожидается | Фактически проверено |
|---|---|---|
| После скачивания до регистрации | Нет регистрации; явный повтор работает | Новый тест реального action с подменённым I/O: PASS; реальный Storage не проверен |
| После сохранения файла до регистрации | Не удалять объект с неопределённым исходом; не объявлять успех | Новый action-тест: PASS; при повторе сохранён первоначальный staging, выполнена одна регистрация; физические файлы не проверены |
| OCR timeout и повтор | Ошибка не подтверждает данные; повтор использует lease | Существующие unit-тесты timeout/busy/reuse; повтор с настоящим HTTP OCR и БД не проверен |
| Поздний старый ответ после новой успешной попытки | Полная строка новой попытки неизменна | Расширен `ocr_lease_fencing.test.sql`: PASS в PGlite; PG16 не проверен |
| Поздний ответ после ручного подтверждения | Подтверждение/автор/время неизменны, begin возвращает reuse | Тот же SQL сравнивает всю строку и количество документов, версий, действующих связей: PASS в PGlite |
| Смена версии при скачивании | Не регистрировать устаревший файл | Новый action-тест: PASS на подменах; настоящий HTTP-сценарий не проверен |
| Отзыв доступа | Отказ без раскрытия ошибки; нельзя принять результат | Существующий action-тест `revoked`: PASS на подменах; отзыв в настоящей БД между HTTP-этапами не проверен |
| Две вкладки | Одна активная попытка, безопасный повтор | Существующий concurrency runner сохранён; новый реальный конкурентный прогон не выполнен |
| Перезапуск с незавершённой операцией | Истёкшая lease не выглядит выполняющейся; проверка результата перед повтором | Unit-тест состояния после expiry: PASS; перезапуск настоящего процесса не проверен |
| Один неудачный файл среди успешных | Отдельные результаты, успешные файлы/подтверждения сохранены | Полный управляемый HTTP-сценарий ещё не подготовлен и не проверен |

Счётчики вызовов в action-тестах **не равны** проверке количества строк настоящей БД.
SQL fixtures не проверяют доступность физических объектов Storage. PGlite не проверяет
конкурентные PostgreSQL-сессии. Компонентный браузерный тест не доказывает безопасное
возобновление через авторизованный интерфейс полного приложения.

## Воспроизведённое несоответствие интерфейса

`processingState` возвращал `failed` для всех временных сбоев. Новый тест сначала упал
с `failed != waiting_retry`. Минимальное исправление только отображает временные
SOURCE_UNAVAILABLE/STORAGE_FAILED/INTERRUPTED как «Ожидает повторения»; неопределённый
исход, доступ, сессия и изменённый источник требуют действия сотрудника.
Подпись явно говорит, что автоматический повтор **не запущен**. Сохранённые состояния
БД, права, lease и ручные подтверждения не изменяются. Проценты не добавлены.

## Блокировки и дальнейшая работа

На момент подготовки локальный Docker Engine недоступен, Supabase CLI отсутствует,
а предыдущий GitHub CI отклонён до запуска из-за оплаты/лимита аккаунта. Не менять
платёжные настройки самостоятельно. Нужна доступная одноразовая инфраструктура для
полного сценария с настоящими Auth/PostgREST/Storage и управляемой HTTP-подменой Drive/OCR.
До прохождения всех девяти сценариев PR должен оставаться черновиком.

Миграций нет. Общие точки пересечения: `processing-status`, тест action импорта,
существующий OCR SQL-тест и браузерный runner статусов. Применять только к согласованной
основе после проверки владельцем; main не изменять.
