# Полные списки справочников

API Supabase отдаёт не больше 1000 строк на запрос. Если список товаров или контрагентов для формы загружать одним запросом, после 1000 записей он молча обрезается: в выпадающем списке не будет части товаров или клиентов, а проверка дублей при импорте контрагентов не увидит часть существующих записей (аудит, находка Н8).

`selectAll` из `src/lib/supabase/select-all.ts` читает выборку страницами по 1000 строк, пока страница не придёт неполной:

```ts
selectAll((from, to) => supabase.from("products").select("id,internal_sku,name").eq("status", "active")
  .order("internal_sku").order("id").range(from, to))
```

- Сортировка должна быть однозначной: в конце всегда уникальный столбец (`id`), иначе страницы могут пропустить или повторить строки.
- Результат имеет привычный вид `{ data, error }`. При ошибке любой страницы `data` пуст, как при ошибке одного запроса.
- Предел — 50 000 строк. Если он достигнут, в журнал сервера пишется сообщение, а результат помечается `truncated`.

Так загружаются списки товаров и контрагентов в формах продаж, поставок, склада, стикеров, финансов, планирования, прогнозов, промо и документов, каталог товаров, а также существующие контрагенты при импорте. Показатели не считаются по загруженным строкам: их считает база (см. `docs/operational-analytics.md`). Если справочник вырастет до тысяч записей, выпадающие списки стоит заменить поиском. Это следующий шаг для удобства, на полноту данных он не влияет.
