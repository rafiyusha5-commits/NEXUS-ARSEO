# Мастер подготовки исторической поставки

Основа: `fix/supplier-quantity-baseline-20261021`, `009a0bedd3a371ceaeee66228e1dae4ca0b040d5` (PR #58). Это проект импорта, **не проведение** исторических операций.

## Как пользоваться

1. В реестре поставок открыть «Подготовить историческую поставку» (`/shipments/prepare`). Выбрать поставку с уже привязанной доступной папкой. Привязка, полный обход и импорт файлов остаются на существующем экране документов. Мастер не выполняет их при открытии.
2. Выбрать подготовку этой поставки либо новой. Новая поставка пока существует только как намерение в проекте: номер, этапы, партии и проводки не создаются.
3. Разнести доступные текущие источники по закупке, импортной перевозке, таможне, продаже и экспортной перевозке. Назначение, оригинал/перевод/копия/новая версия — явные отметки проекта, а не подтверждение истинности. Автомобиль определяется только существующей привязкой Nexus. Номер, язык и имя папки не используются для классификации.
4. Проверить значения и ссылки на конкретные версии. Отдельно видны прочитанное, подтверждённое, предположение, отсутствие данных и противоречие. Подтверждённое чтение не является приёмкой. Сопоставление количеств использует существующий `analyseDocumentQuantities`; копии и переводы не суммируются.
5. Сохранить черновик и продолжить его из списка. Только явное сохранение меняет проект. Последний этап перечисляет действия для ручного разбора. Применения к поставке в этом выпуске нет.

## Повторное использование и защита

- `shipment_drive_folders`, существующие bind/scan/import/check/link и экран сопоставления — без нового импортёра.
- Тот же серверный Drive gateway с пользовательской сессией, без `service_role`. RLS и личные запреты действуют на таблицу и RPC. Live-проверка доступности папки выполняется при открытии/сохранении; значения Nexus проверяются по текущей версии, статусу и точной активной привязке через `usableSourceContext`.
- `SOURCE_FIELD_DEFINITIONS`, `conflictsAcrossDocuments` и существующий анализ товарных строк. Сравнение разделено по выбранной операции и автомобильному контексту; неизвестный контекст не угадывается.
- В базе проекта — только ID источников, версии, время результата чтения и ограниченные перечисления. Тексты/цены/прочитанные значения не копируются в черновик. UI получает проекцию полей, а не произвольный текст распознавания.
- Повтор того же сохранения возвращает прежнюю ревизию. Изменённый проект другого окна отклоняется. При смене версии/результата чтения назначения сбрасываются для повторного разбора; подтверждённые данные источника не меняются. Недоступные/отвязанные/архивные источники не отправляются в компонент.
- Пустая/неполная выборка не означает готовность. Нет утверждения «всё готово к проведению».

## Миграция

`202610210200_historical_preparation.sql`: новая таблица проектов, RLS, защитный триггер и invoker RPC. Только добавление; исходные документы, подтверждения, количества, остатки и финансы не обновляются. Владелец применяет после согласованной основы. Повторное применение проверяет общий SQL-набор. Рабочие/учебные базы не используются.

## Проверки

```text
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm test
corepack pnpm build
corepack pnpm test:db
node scripts/test-preparation-ui.mjs <path-to-playwright> <screenshot-directory>
node scripts/test-historical-shipment.mjs
```

`test:db` требует PostgreSQL 16; скрипт сам создаёт одноразовый кластер. Последняя команда использует существующий изолированный браузерный пилот: реальный Next/Auth/PostgREST/Storage, синтетические Drive/OCR. Нужны Docker, тестовые образы, Supabase CLI и Playwright согласно `docs/historical-shipment-browser-e2e.md`. Не передавать URL базы владельца или настоящие ключи.

| Комплект/действие | Проверяемое поведение |
|---|---|
| Полный синтетический | Значения с источником, существующее сопоставление 965 шт., без записи количеств |
| Неполный / обрезанный | Нет ложной готовности; конкретные действия, отсутствующее не равно нулю |
| Два автомобиля + перевод | Раздельный контекст; противоречие CMR-A/перевод видно, CMR-B не смешивается |
| Повтор/новое окно | Один ID/ревизия при повторе; сохранение в PostgreSQL и восстановление через браузер |
| Смена/отзыв источника | Старые назначения не принимаются; скрытые значения не выводятся |
| Прямой RPC/REST | Личные запреты, владелец проекта, отсутствие gateway, неизвестные поля, устаревшая ревизия |
| Побочные изменения | SQL/браузер сравнивают документы, подтверждения, товарные строки, движения и расходы до/после |

## Границы первого выпуска

- Выбирается уже привязанная папка. Отдельного каталога произвольных новых папок и новой транспортной модели нет. Непривязанная папка подключается штатным механизмом.
- Разбор продолжает существующие источники поставки. Новый целевой проект не создаёт новую поставку и не переносит чужие подтверждения/автомобильные связи.
- Сохранённый полный обход папки имеет показанную дату; это не обещание актуальности каждого файла Drive в реальном времени. Повторный обход — существующая явная операция. Открытие мастера не запускает OCR/LLM.
- Оригинал/перевод/копия/новая версия отмечаются сотрудником для разбора. Автоматической юридической эквивалентности, объединения файлов и отдельного связывания переводов нет.
- Значения, не поддержанные существующим извлечением, не угадываются. Полнота бизнес-комплекта и применимость разделов требуют проверки сотрудником.
- Черновики персональные, без совместного редактирования и без журнала версий проекта. История/подтверждения исходных документов остаются в существующих механизмах.
- Реальные документы компании, архив HS-39 и реальные внешние сервисы не проверены. Зелёные синтетические тесты не доказывают совместимость с ними.
