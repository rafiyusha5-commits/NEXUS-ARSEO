# Дашборд руководителя (блок Д)

Миграция `202611280400_executive_dashboard.sql`, экран `/dashboard`. Решения владельца `damirator1-afk` от 28.11.2026:
приняты все решения задания по умолчанию (Д1–Д4). Основан на платёжном календаре (блок Б,
[cash-calendar.md](cash-calendar.md)) и отчёте о потерях (блок Г, [losses.md](losses.md)).

## Кто видит (Д1, Д2)

- Право `dashboard.executive.view` — администратор, директор, исполнительный, коммерческий и логистический директора.
- Каждая плитка — только при правах на её данные; без них плитки нет ни на экране, ни в ответе функции:

  | Плитка | Нужные права |
  | --- | --- |
  | Выручка и маржа | «Отчёты: просмотр» + закупочные цены |
  | Просроченные долги клиентов | «Дебиторка: просмотр» |
  | К оплате поставщикам, Прогноз денег | «Финансы: просмотр» |
  | Сроки годности | «Отчёты» + «Остатки» |
  | Поставки | «Отчёты» + «Поставки» |
  | Требует решения | всегда; заказы без цены — с «Заказы: просмотр», задачи — с «Задачи: просмотр» |

- Для этих ролей дашборд — стартовая страница: «/» ведёт на `/dashboard`. «Сводка дня» открывается ссылкой в шапке дашборда (`/?view=overview`).

## Плитки

| Плитка | Что показывает | Откуда (та же функция, что у отчёта) |
| --- | --- | --- |
| Выручка и маржа | выручка без НДС, прибыль, маржа, доля выручки с полными данными; к прошлому месяцу | `profitability_report` за месяц и за прошлый месяц |
| Просроченные долги клиентов | сумма по валютам, оценка в тенге, 5 крупнейших должников | `customer_receivables` |
| К оплате поставщикам | на 14 дней по плановой дате оплаты (иначе по сроку) и просроченное | `cash_payables_due(14)` — выплаты платёжного календаря; просрочка — `payables_summary` |
| Прогноз денег | ближайший кассовый разрыв: валюта, день, неделя; по каждой валюте | `cash_calendar('week', 13)` |
| Сроки годности | товар под риском по себестоимости (истёк, до 30, до 90 дней), потери месяца к прошлому | `loss_risk`, `loss_report` |
| Поставки | машины в пути, поставки с опозданием, просроченные и заблокированные этапы | `operational_summary` и рейсы открытых поставок |
| Требует решения | непрочитанные согласования, «Проверьте цену», «Заказ нельзя отгрузить», просроченные задачи, заказы со строкой без цены | уведомления сотрудника, задачи, заказы |

Пометка «данные неполные» появляется, когда в источнике есть строки без курса, себестоимости или цены, или когда
права скрывают часть данных (без оплат за товар, без долгов клиентов). Для прогноза денег пометка ставится и когда у
валюты не введён остаток на счетах.

## Правила

- Плитки считает функция базы `executive_dashboard_tile(плитка, месяц)`. Она вызывает функции исходных отчётов и
  только выбирает и складывает то, что они вернули. Работает с правами самого сотрудника (security invoker): задачи,
  уведомления, заказы и поставки читаются через те же политики, что на их экранах. Страница ничего не считает.
- Все семь плиток запрашиваются одной волной, параллельно, — страница ждёт самую медленную, а не их сумму.
- Ошибка одной плитки не ломает остальные: такая плитка показывает «нет данных» и ссылку на исходный отчёт, а не ноль.
- Суммы — по валютам. Тенге — оценка по официальному курсу на сегодня (`dashboard_rate_kzt`, последний курс за 7 дней), без курса — пометка (Д3).
- Месяц — текущий к прошлому, переключается стрелками (Д4). Месяц влияет на выручку и потери; долги, оплаты,
  прогноз денег, поставки и решения — на сегодня.
- На телефоне плитки идут одной колонкой без горизонтальной прокрутки.

## Ассистент

Отчёт `executive_dashboard` (только чтение, право дашборда): все плитки сотрудника, в том числе плитки с ошибкой.

## Проверки

- **Плитка = исходный отчёт на тех же данных** — проверки добавлены в тесты источников:
  - `profitability.test.sql` — выручка, прибыль, маржа за месяц и прошлый месяц;
  - `loss_report.test.sql` — риск по срокам и потери;
  - `cash_calendar.test.sql` — к оплате, просрочка, разрыв, дебиторка, с ручными значениями.
- **Права:** без права на данные плитки нет — ни в ответе функции, ни на экране.
- **`executive_dashboard.test.sql`:**
  - кто видит дашборд и какие плитки;
  - «Поставки» = `operational_summary`;
  - «Требует решения» — только свои уведомления;
  - дашборд целиком = плитки по одной;
  - отказ источника: плитка «error» без цифр, остальные шесть на месте.
- **Проверка поломкой:** если плитка дебиторки посчитает и непросроченный долг, сверка с реестром падает (`overdue receivables = the register`).
- **`scripts/test-executive-dashboard-ui.mjs`** — настоящие плитки на синтетических данных в браузере:
  - 7 плиток, плитка с ошибкой без нуля, пометки неполных данных;
  - на ширине 390 — одна колонка без горизонтальной прокрутки;
  - скриншоты `docs/screenshots/executive-dashboard-1440.png` и `-390.png`.
