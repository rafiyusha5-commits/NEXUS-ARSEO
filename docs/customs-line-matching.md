# Явное сопоставление товарных строк ДТ

На вкладке «Документы», в результате чтения ДТ, сотрудник с правами
`source_documents.review`, `shipments.view`, `documents.view`, `products.view`
выбирает подтверждённые инвойс и упаковочный лист. Все три источника должны
относиться к одной поставке и одной области перевозки.

Для каждой строки ДТ выбираются товар Nexus, строка инвойса и строка упаковочного
листа. Выбор не заполняется автоматически по порядку, похожему названию или
количеству. Обязательны основание и подтверждение сверки оригиналов.
Если в документе прочитан другой артикул, заменить его сопоставлением нельзя.

`shipment_customs_matches` хранит неизменяемые редакции: источники и их снимки,
связи строк, основание, автор, время. Повтор той же операции возвращает прежнюю
редакцию. Для изменения нужна актуальная редакция страницы; конкурентные записи
сериализуются блокировками документов и распознаваний. Прямой INSERT/UPDATE/DELETE
для пользователей и service_role не разрешён.

Сохраняется оригинальный `extracted_data`. Для сравнения создаётся временная
проекция с артикулами из отдельного сопоставления. Из предупреждений проекции
убирается только предупреждение об отсутствующем артикуле, если количество и
единица прочитаны. Оригинальные предупреждения остаются видимыми. Числовые
расхождения, неизвестные поля и остальные предупреждения не исчезают.

Подтверждение чтения ДТ — отдельное действие, использующее точную редакцию
сопоставления. В `confirmed_data` сохраняется исходная ДТ без выдуманных артикулов,
результат проверки и идентификатор сопоставления. Прежние ручные поля сохраняются.
Старый RPC подтверждения остаётся строгим и не принимает строки без артикула.

Новая версия файла, изменение распознавания, ручных реквизитов, привязки к машине,
недоступность источника или изменение артикула товара делают сопоставление
непригодным для новой сверки. Старое подтверждение остаётся историческим фактом;
экран не представляет его как подтверждение актуального сопоставления.

Ограничение первой версии: полное взаимно однозначное сопоставление строк всех
трёх документов, один товар на строку. Агрегированные строки ДТ, разделение одного
товара на несколько строк и документы с разной областью перевозки требуют
отдельного разбора; система не подбирает связи автоматически.

Приёмка, количества поставки, склад, цены, расходы, платежи и справочник упаковок
этими операциями не изменяются. Число паллет и масса упаковки в оригинале остаются
отдельными сведениями от расчёта по справочнику.
