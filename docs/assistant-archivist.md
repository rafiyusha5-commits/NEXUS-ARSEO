## Проверка и включение

После прежних миграций 5200–5500 требуется `202609275600_agent_archivist.sql`: она расширяет только строгий формат служебной трассы. Бизнес-таблицы, роли и бюджет не меняются. Повторное применение допустимо.

Рекомендуемые ограничения пилота для сложных запросов: `AGENT_MAX_INPUT_TOKENS=55000`, `AGENT_MAX_OUTPUT_TOKENS=9000`. При тарифах ввода $2/M и вывода $12/M резерв модели равен $0.273; с голосом $0.293, в пределах прежнего резерва $0.30. Общий бюджет остаётся $5/месяц, лимит 20 вопросов/сутки. Реальный расход, а не резерв, записывается после ответа. В оценку входа входит размер определений инструментов.

Проверки прав выполняются при формировании доступных разделов, перед каждым инструментом, в слое Supabase и перед выдачей ответа. Для обычных таблиц также заново проверяется RLS видимость конкретных записей, включая смену ответственного. Перед отправкой в Telegram проверки повторяются. Условно закрытые строки договоров с закупочными ценами и расходы на стоимость товара требуют prices.purchase.view. Данные калькулятора с закупочными значениями читаются отдельным разделом calculator_finance.

Телефоны, контакты и публичные идентификаторы подставляет код из разрешённых записей; сами значения скрыты от модели. Паспортные номера, удостоверения, секреты и настройки подключения не выдаются. Финансовые суммы и валюты берутся только из разрешённых структурированных полей, а не из расчётов модели.

Страница поиска содержит не больше 20 записей; неполный результат отмечается, доступны offset и фильтры. Ответ показывает выбранные проверенные поля; промежуточные карточки поиска не добавляются к конкретному вопросу. Если модель не выбрала факты, код использует полные разрешённые карточки как запасной вариант. Точное совпадение артикула имеет приоритет над поиском по части строки. Ассортимент find_products отдельно собирается до 200 товаров. Длинный ответ Telegram приходит одним UTF-8 файлом, короткий — текстом. Повторной доставки при неизвестном исходе нет.

## Границы

Покрыты структурированные рабочие данные и сохранённый снимок калькулятора. Исходные PDF, DOCX, фотографии и сканы не становятся автоматически полнотекстовым архивом: для них доступны реквизиты и существующие результаты OCR; полный поиск по содержимому потребует отдельного индексирования. Ассистент не создаёт заказы, не меняет статусы, не назначает роли, не отправляет сообщения другим людям.

Административные сведения доступны только по соответствующим правам; пароли, Auth-токены и секреты интеграций исключены. Наличие поля в будущей миграции не открывает его автоматически: реестр расширяется явно и проверяется SQL-тестом против окончательной схемы.

Локальный polling работает пока компьютер и Nexus включены. Для круглосуточного доступа из поездки необходим постоянный интернет-хостинг приложения и обработки Telegram. Это не включается самим расширением данных.

## Примеры приёмки

- «Белки, жиры и углеводы товара <артикул>»: значения, основа (на 100 г/100 мл/порцию), ссылка на товар; отсутствующее значение не равно нулю.
- «Сколько штук и какой вес в коробе <артикул>»: упаковка по product_id.
- «Телефон водителя по поставке <номер>»: проверенный контакт в личном чате; номер удостоверения скрыт.
- «Какая закупочная цена <артикул>»: сумма и валюта при products.view + prices.purchase.view; без прав раздел не предлагается и прямой вызов отклоняется.
- «Себестоимость своей поставки»: существующий расчёт и версия; чужая назначенная поставка не читается при costing.view_assigned.
- «Планы закупок на октябрь»: заголовки; товарные строки дополнительно требуют purchase_plans.detail.
- Отзыв финансового права, смена ответственного или перепривязка Telegram во время обработки: ответ с данными не доставляется.
