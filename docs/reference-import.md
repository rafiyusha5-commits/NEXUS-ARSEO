# Импорт справочника контрагентов и товаров

Транзакционный и идемпотентный импорт очищенного справочника: контрагенты с ролями, карточки товаров, идентификаторы (GTIN, штрихкоды, артикулы поставщиков) и уровни упаковки.

- Миграция: `supabase/migrations/202609271900_reference_data_import.sql`. Применяется после всех предыдущих.
- Экран: «Товары» → «Импорт справочника» (`/products/import`).
- Функция базы: `public.import_reference_data(p_payload jsonb, p_dry_run boolean default true)`.
- Пример пакета: [`reference-import.example.json`](reference-import.example.json) — он же отдаётся как шаблон JSON.

## Что загружается и что нет

| Загружается | Не загружается |
|---|---|
| Контрагенты: название, краткое название, роли, страна, БИН/ИНН, рег. номер, сайт, язык | Цены, себестоимость, маржа, наценки, скидки, бонусы |
| Товары: артикул, названия (ru, en, kk), производитель, бренд, страна происхождения, ТН ВЭД, срок годности, состав, КБЖУ, температурный режим, базовая единица, стикеровка, маркировка, статус | Валюта, договоры, условия оплаты и поставки, требования клиента к остаточному сроку годности |
| Идентификаторы: GTIN, штрихкод единицы, штрихкод короба, артикул поставщика | Контакты, примечания контрагентов |
| Упаковка: вложение, вес брутто/нетто, объём, габариты по уровням | Архивирование и удаление записей |

Поле или колонка, похожие на цену или коммерческое условие (`price`, `cost`, `margin`, `цена`, `себестоимость`, `договор`, `оплата`, `валюта` и т. п.), **не пропускаются молча**, а отклоняют файл. Так конфиденциальные данные не попадут в базу по ошибке.

Исходные Excel-файлы с ценами и условиями, извлечённые из них данные и `.env.local` не добавляются в Git, тестовые фикстуры и логи. Папка `local-imports/` исключена в `.gitignore`. Сервер не пишет содержимое пакета в логи.

## Порядок работы

1. Подготовить очищенный файл: JSON-пакет или таблицы (CSV / XLSX) по шаблонам.
2. На экране импорта выбрать файлы. Браузер читает их и проверяет формат. Ошибки показываются со ссылкой на файл, лист и строку.
3. Нажать «Проверить без записи» (dry-run). База выполняет весь импорт и откатывает его. Отчёт показывает по каждой строке одно из действий: **создание**, **обновление**, **без изменений**, **конфликт** или **ошибка**.
4. Если конфликтов и ошибок нет и есть что менять, нажать «Импортировать». Весь пакет записывается одной транзакцией.
5. Повторная загрузка того же файла ничего не меняет: все строки получают статус «без изменений».

Кнопка «Импортировать» доступна, только если предпросмотр выполнен **для этого же пакета**. Даже в обход интерфейса база откажет в записи, если найдёт хоть один конфликт или ошибку. Такой отказ приходит с кодом `NX422`: «Импорт отменён: конфликтов N, ошибок M. Ни одна запись не сохранена».

## Формат JSON (канонический)

```json
{
  "format": "nexus-reference-import",
  "version": 1,
  "counterparties": [ { "ref": "demo-maker", "legal_name": "…", "roles": ["manufacturer", "supplier"], "country": "FI" } ],
  "products": [ { "internal_sku": "DEMO-001", "name": { "ru": "…" }, "manufacturer": "demo-maker", "identifiers": [], "packaging": [] } ]
}
```

Полный пример — [`reference-import.example.json`](reference-import.example.json). Любой ключ вне списков ниже — ошибка строки.

### counterparties[]

| Поле | Тип | Обяз. | Правила |
|---|---|---|---|
| `row` | число | нет | номер строки источника для отчёта |
| `ref` | строка ≤ 300 | нет | ключ для ссылок из товаров. По умолчанию — `tax_id`, иначе `legal_name` |
| `legal_name` | строка ≤ 300 | да | |
| `short_name` | строка ≤ 200 | нет | |
| `roles` | массив | да | `manufacturer`, `supplier`, `customer`, `carrier`, `broker`, `printing_house`, `other` |
| `country` | строка | да | ISO 3166-1 alpha-2: `KZ`, `FI` |
| `tax_id` | строка ≤ 50 | нет | БИН / ИНН / VAT |
| `registration_number` | строка ≤ 100 | нет | |
| `website` | строка ≤ 300 | нет | |
| `preferred_locale` | строка | нет | `ru`, `kk`, `en` |

### products[]

| Поле | Тип | Обяз. | Правила |
|---|---|---|---|
| `row` | число | нет | номер строки источника |
| `internal_sku` | строка ≤ 64 | да | ключ сопоставления товара |
| `name` | `{ru, en, kk}` или строка | для нового товара — `ru` | каждое значение ≤ 300; строка = `{ru}` |
| `manufacturer` | строка | для нового товара | ссылка на контрагента с ролью `manufacturer` (см. «Ссылки на контрагентов») |
| `brand` | строка ≤ 200 | нет | |
| `country_of_origin` | строка | нет | ISO alpha-2 |
| `hs_code` | строка | нет | ТН ВЭД: 4, 6, 8 или 10 цифр |
| `shelf_life_days` | целое 1–36500 | нет | полный срок годности, дней |
| `composition` | `{ru, en, kk}` или строка | нет | каждое значение ≤ 4000 |
| `nutrition_facts` | объект | нет | `basis` (`100g`, `100ml`, `serving`; по умолчанию на 100 г), `energy_kcal`, `energy_kj`, `protein_g`, `fat_g`, `saturated_fat_g`, `carbohydrates_g`, `sugars_g`, `fiber_g`, `salt_g`. Значения ≥ 0, до 3 знаков после запятой; граммы на 100 г/мл — не больше 100 |
| `temperature_regime` | строка | нет | `frozen`, `chilled`, `ambient` |
| `temperature_range` | строка ≤ 50 | нет | например «+2…+6 °C». В таблицах можно вместо неё указать `temperature_min_c` и `temperature_max_c` |
| `base_uom` | строка | нет | `piece` (по умолчанию), `box`, `layer`, `pallet`, `truck` |
| `requires_sticker`, `requires_marking` | boolean | нет | для нового товара по умолчанию `false` |
| `status` | строка | нет | `draft`, `active`, `discontinued`. Новый товар по умолчанию `active` |
| `identifiers` | массив ≤ 20 | нет | см. ниже |
| `packaging` | массив ≤ 5 | нет | см. ниже |

### identifiers[]

| Поле | Правила |
|---|---|
| `type` | `gtin`, `unit_barcode`, `box_barcode`, `supplier_sku` |
| `value` | `gtin` — 8, 12, 13 или 14 цифр с верной контрольной цифрой GS1. Штрихкоды единицы и короба — 4–48 латинских букв, цифр или дефисов. `supplier_sku` — строка ≤ 100 |
| `counterparty` | только для `supplier_sku`, обязательно. Контрагент с ролью `supplier` или `manufacturer` |
| `packaging_uom` | уровень упаковки штрихкода (`piece`, `box`…) |
| `is_primary` | boolean |

### packaging[]

| Поле | Правила |
|---|---|
| `uom` | `piece`, `box`, `layer`, `pallet`, `truck`; каждый уровень у товара один раз |
| `units_per_parent` | > 0, до 3 знаков; обязательно для нового уровня. Сколько единиц предыдущего уровня в этом: штук в коробе, коробов в слое… |
| `gross_weight_kg`, `net_weight_kg` | ≥ 0, до 3 знаков; нетто не больше брутто |
| `volume_m3` | ≥ 0, до 4 знаков |
| `length_cm`, `width_cm`, `height_cm` | ≥ 0, до 2 знаков |

## Таблицы (CSV, TSV, XLSX)

Можно загрузить несколько CSV-файлов или один XLSX с несколькими листами. Тип таблицы определяется по заголовкам:

| Таблица | Обязательные колонки | Шаблон |
|---|---|---|
| Контрагенты | `legal_name`, `roles` | `/products/import/template?kind=counterparties` |
| Товары | `internal_sku` | `/products/import/template?kind=products` |
| Идентификаторы | `internal_sku`, `identifier_type`, `value` | `/products/import/template?kind=identifiers` |
| Упаковка | `internal_sku`, `uom`, `units_per_parent` | `/products/import/template?kind=packaging` |

- Колонки товаров совпадают с полями JSON. Исключения:
  - названия и состав разбиты на колонки `name_ru`/`name_en`/`name_kk` и `composition_ru`/`composition_en`/`composition_kk`;
  - КБЖУ — отдельные колонки `nutrition_basis`, `energy_kcal`, `protein_g`…;
  - для быстрого заполнения есть колонки `gtin` (основной), `unit_barcode`, `box_barcode` (уровень `box`), `supplier_sku` и `supplier`. Артикул поставщика привязывается к `supplier`, а без него — к `manufacturer`. Колонка `supplier` без `supplier_sku` — ошибка.
- Заголовки можно писать по-русски: «Внутренний артикул», «Наименование», «Производитель», «Срок годности, дней», «ТН ВЭД», «Стикеровка», «Вес брутто, кг» и т. п. Полный список — `TABLE_COLUMNS` в `src/lib/reference-import/tables.ts`.
- Неизвестная колонка — ошибка, а не пропуск. Удалите лишние колонки перед загрузкой.
- Строки идентификаторов и упаковки присоединяются к товару с тем же `internal_sku`. Если товара нет в таблице товаров, строка считается обновлением существующего товара.
- CSV: разделитель `;`, `,` или табуляция определяется по первой строке. Кодировка UTF-8, BOM допускается.

### Нормализация значений

| Значение | Правило |
|---|---|
| Текст | обрезаются пробелы по краям, повторные пробелы, неразрывные и невидимые символы; Unicode NFC |
| Числа | «1 200,5», «1.200,5», «1,200.5», «2,8» и числа Excel. Одиночная запятая — десятичный разделитель: «1,200» = 1,2 |
| Да/нет | да, нет, yes, no, 1, 0, true, false, +, − |
| Роли | английские коды или «производитель», «поставщик», «клиент», «перевозчик», «брокер», «типография», «другое»; разделители `\|`, `,`, `;`, `/` |
| Упаковка | шт, короб/коробка, слой, паллета/поддон, фура и английские коды |
| Температурный режим | заморозка, охлаждённый, комнатная и английские коды |
| ТН ВЭД | пробелы и точки удаляются. Если Excel сохранил код числом и потерял ведущий ноль (0402…), ноль возвращается. В тексте нечётное число цифр — ошибка |
| GTIN | пробелы и дефисы удаляются, проверяется контрольная цифра |

## Правила сопоставления

**Контрагент** ищется так:
1. По `country` + `tax_id`, если БИН/ИНН указан.
2. Иначе — по стране и юридическому названию без учёта регистра.

Результат поиска:
- найден один — обновление;
- не найден — создание;
- найдено несколько — конфликт;
- найден по названию, но с другим БИН/ИНН — конфликт;
- найден, но в архиве — конфликт;
- две строки пакета указывают на одного контрагента — конфликт.

**Товар** сопоставляется по `internal_sku`. Повтор артикула в пакете — конфликт. Товар в архиве — конфликт.

**Штрихкоды** (GTIN, штрихкод единицы, штрихкод короба) сопоставляются по типу и значению. Сравнение числовых кодов — в форме GTIN-14, поэтому `4601234567890` и `04601234567890` — один код. Один код не может принадлежать разным товарам, в каком бы типе он ни был записан. Если код уже у другого товара или повторяется у двух товаров пакета — конфликт. Это правило действует и вне импорта: триггер `guard_product_barcode` отклоняет любую запись в `product_identifiers`, которая отдала бы код второму товару.

**Артикул поставщика** сопоставляется по контрагенту и значению. Если он принадлежит другому товару — конфликт.

**Упаковка** сопоставляется по товару и уровню.

### Ссылки на контрагентов

`manufacturer` и `identifiers[].counterparty` ищутся:
1. Среди контрагентов этого пакета по `ref` (без учёта регистра).
2. Если там нет — среди существующих неархивных контрагентов по `tax_id` или точному юридическому названию.

Если найдено несколько — конфликт; если не найдено — ошибка. Если контрагент из пакета сам получил конфликт или ошибку, ссылающийся товар тоже получает ошибку.

Роли проверяются после применения строк контрагентов этого пакета:
- производитель должен иметь роль `manufacturer`;
- владелец артикула поставщика — роль `supplier` или `manufacturer`.

Ссылаться можно только на контрагента, которого пользователь вправе видеть.

### Обновление

- Поле, которого нет в файле (или пустое), **не меняется**. Очистить значение импортом нельзя.
- Названия и состав объединяются по языкам. Если в файле только `kk`, названия `ru` и `en` сохраняются. КБЖУ объединяется по показателям.
- Роли контрагента только добавляются. Роль, которой нет в файле, не удаляется: от неё могут зависеть товары и документы.
- Идентификаторы и уровни упаковки, которых нет в файле, не удаляются.
- Строка без фактических изменений не перезаписывается: `updated_at` и журнал аудита не меняются.

## Права

- Запустить импорт (и dry-run) может только сотрудник с правами **«Товары: создание»** и **«Товары: изменение»** (`products.create` и `products.update`). Без них функция отвечает ошибкой `42501`, а экран показывает сообщение вместо формы. По матрице миграции `202609270002` это администратор, директор, исполнительный директор, директор по логистике, старший менеджер и специалист по логистике.
- Строки контрагентов проверяются так же, как политики RLS таблицы `counterparties` (`private.can_access_counterparty`). Создание требует `*.create`, изменение — `*.update`, строка без изменений — `*.view`. Модуль прав выбирается по ролям: `customers.*` для клиентов, `suppliers.*` для остальных. Нехватка прав — ошибка строки, весь пакет не записывается.
- `anon` не может вызвать функцию. Рабочая функция `private.run_reference_import` недоступна напрямую. Функция импорта — `SECURITY DEFINER` с `search_path = ''`, права проверяются явно в её начале.
- Журнал аудита (`audit_log`) записывает каждое созданное и изменённое значение от имени пользователя, запустившего импорт.

## Транзакционность и dry-run

- Вызов функции — одна транзакция. Строки обрабатываются по порядку: сначала контрагенты, затем товары с идентификаторами и упаковкой.
- Каждая строка выполняется во вложенном блоке. Ошибка строки попадает в отчёт, а не прерывает проверку остальных строк.
- В режиме записи при любом конфликте или ошибке функция в конце вызывает исключение. Откатывается **весь** пакет, включая уже обработанные строки.
- Dry-run выполняет ту же запись внутри точки сохранения и всегда откатывает её. Отчёт предпросмотра поэтому учитывает ограничения и триггеры базы. Журнал аудита после dry-run не меняется.
- Одновременно выполняется только один импорт (`pg_advisory_xact_lock`).

## Ограничения

- Не больше **1000 контрагентов** и **1000 товаров** за раз, у товара — не больше 20 идентификаторов и 5 уровней упаковки. Размер пакета не больше 4 МБ, файла — не больше 10 МБ.
- На локальном PostgreSQL 16 пакет из 2000 товаров с 6 строками каждый (12 000 строк отчёта) обрабатывается за ~3,5 с, повторный — за ~1,2 с. В Supabase у роли `authenticated` по умолчанию `statement_timeout` = 8 с, поэтому лимит — 1000 товаров. Большой справочник загружается несколькими пакетами, каждый — отдельной транзакцией.
- Импорт не очищает поля, не удаляет роли, идентификаторы и уровни упаковки и не архивирует записи.
- Контрагента нельзя «переименовать» в другую страну. Смена страны создаёт нового контрагента.
- Уже существующие в базе совпадения штрихкодов между товарами (если такие были до миграции) триггер не исправляет. Он запрещает только новые.

## Проверки

- `supabase/tests/reference_import.test.sql` проверяет:
  - права (бухгалтер и коммерческий директор не запускают импорт; специалист без права создания поставщиков не создаёт контрагента);
  - что dry-run ничего не пишет, включая журнал аудита;
  - запись и повторный импорт без изменений;
  - слияние при обновлении;
  - конфликты GTIN: чужой код, GTIN-13 против GTIN-14, дубль в пакете, прямую вставку мимо импорта;
  - отмену всего пакета из-за одной строки;
  - роли производителя и поставщика;
  - отказ по полю цены;
  - что пример из документации принимается базой.
- `tests/reference-import/*.test.ts` — модульные тесты нормализации строк, чисел, кодов и справочников, разбора CSV и таблиц, пакета JSON и отчёта.
