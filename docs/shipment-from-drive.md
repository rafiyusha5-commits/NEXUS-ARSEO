# Поставка из папки заказа на Google Drive

Экран `/shipments/from-drive` (кнопка «Создать из папки заказа на Drive» в разделе поставок).

1. **Папка заказа.** Nexus показывает папки из «Будущих заказов» (корень `FUTURE_ORDERS_DRIVE_ROOT`).
   Уже привязанные к поставке папки ведут на эту поставку. Папку из архива можно открыть по ссылке —
   она должна лежать внутри одного из двух разрешённых деревьев Drive.
2. **Карточка.** По названию папки и её вложенных папок предлагаются:
   - код проекта — коды заказов из названия (`AB-50`, `Cdx12` → `Cd-12`; номер архива `04_03_` отбрасывается);
   - клиент — по справочнику префиксов, если клиент один; свои склады — без клиента;
   - поставщик — если отличительное слово его названия есть в названии папки и такой поставщик один;
   - маршрут и валюта — как в последней поставке этого поставщика; маршрут иначе — единственный из его страны в KZ;
   - склад — Актобе.
   Всё можно изменить. Ничего не сохраняется до нажатия кнопки.
3. **«Создать поставку и привязать папку».** Создаётся поставка с номером и этапами (`create_shipment_with_stages`)
   и привязка папки (`bind_shipment_drive_folder` через серверный шлюз Drive). Если привязка не удалась, поставка
   остаётся, а экран документов предлагает привязать папку по ссылке.

Документы из папки этот шаг не загружает: их проверка и загрузка — на вкладке «Документы» поставки.
Google Drive только читается (GET, `drive.readonly`).

## Префиксы заказов

Таблица `public.order_prefixes` (миграция `202611220200_order_prefixes.sql`): префикс (1–12 латинских букв, без учёта
регистра), клиент или признак «свои склады», примечание. Читается с `shipments.view`, меняется функциями
`set_order_prefix` / `remove_order_prefix` с `shipments.create`. Список вносится на экране, не в миграции.

## Права

Создание из папки требует прав привязки папки (`shipments.view`, `shipments.update`, `documents.view`,
`documents.drive.view`, `prices.purchase.view`) и `shipments.create`.

## Документы из папки (вкладка «Документы» поставки)

- **Предложенный тип.** Для каждого файла Nexus предлагает тип документа: сначала по имени файла (договор-заявка,
  CMR, инвойс, упаковочный лист, спецификация, ДТ, сертификат, контракт, СНТ, ТТН, стикер, коды маркировки и др.),
  если имя ничего не говорит — по подпапке («Результат растаможки» → таможенная декларация, «ЧЗ» → коды маркировки,
  «Стикеры» → макет стикера). Правила — `src/lib/google/document-classify.ts`. Тип только предлагается: сотрудник
  видит его выбранным и подтверждает или меняет.
- **«Загрузить отмеченные».** Блок «Загрузить несколько файлов» перечисляет файлы, которых ещё нет в Nexus. Отмечены
  файлы с предложенным типом; за раз — до 25. Каждый файл проходит ту же проверку и учёт операции, что и загрузка по
  одному. Файл без типа не загружается и называется в итоговом сообщении.
- **«Обновить из Drive».** После первой проверки кнопка «Проверить папку» называется «Обновить из Drive». Сообщение
  называет число новых файлов с прошлой проверки; у файлов, которых ещё нет в Nexus, отметка «Ещё не в Nexus» и дата,
  с которой файл есть в папке.
- **Уведомление.** Если повторная проверка нашла новые файлы, ответственный за поставку получает уведомление
  «Новые файлы в папке Drive» со ссылкой на папку поставки — один раз за проверку. Первая проверка папки и проверка,
  которую выполнил сам ответственный, уведомлений не создают. В тексте нет имён файлов. Миграция
  `202611220300_drive_new_files.sql` (столбец `first_seen_at`, тип уведомления `drive_new_files`, триггер). В Telegram
  этот тип не отправляется.

Автоматической проверки папок по расписанию нет: Nexus проверяет папку по кнопке.

Проверки: `tests/google/document-classify.test.ts`, пакетная загрузка в `tests/shipment-drive-import.test.ts`,
`supabase/tests/drive_new_files.test.sql`.

## Сверка с «Вн расчетами»

Если в сохранённом списке папки поставки есть таблица «Вн расчеты …» (не «Копия …»), на вкладке «Документы» появляется
кнопка «Сверить поставку с «Вн расчетами»» — экран `/shipments/<id>/workbook`.

- **Чтение.** Перед чтением Nexus проверяет на Drive, что таблица по-прежнему лежит в привязанной папке. Затем через
  Google Sheets (только чтение, `spreadsheets.readonly`) читает два листа: «Расчеты» и «От клиента». Таблицы весят
  десятки мегабайт, поэтому файл целиком не скачивается.
- **Что берётся.** Строки закупа листа «Расчеты»: артикул ARSEO, артикул завода, штрихкод товара, «Заказ, шт» и
  «Цена за ед, евро (INVOICE)» блока «ЗАКУП у поставщика»; «Дата погрузки на заводе» и «Дата выгрузки на РЦ» над
  заголовками; номер и дата заказа клиента и контракта с листа «От клиента». **Не берутся** продажные цены,
  «Экономика», «MasterData», «Годен до».
- **Сопоставление товара:** артикул ARSEO (без учёта пробелов), затем артикул завода этого поставщика, затем
  штрихкод. Если ключ подходит нескольким товарам, строка не сопоставляется.
- **Сверка.** Для каждой строки: новая позиция, изменится (количество или цена), совпадает, распределена по машинам
  (не меняется здесь) или не сопоставлена. Позиции поставки, которых нет в таблице, только показываются.
- **Применение.** Отмеченные изменения и дата готовности (= дата погрузки на заводе) применяются одной транзакцией
  функцией `apply_order_workbook` (миграция `202611220400_order_workbook.sql`) через существующие функции позиций:
  права, закупочные цены и правила приёмки те же. Если позиция изменилась после просмотра, не применяется ничего.
  Цены таблицы — в евро; цена позиции в другой валюте не меняется. Дата выгрузки на РЦ клиента в поставку не
  переносится.

Проверки: `tests/shipments/order-workbook.test.ts` (синтетический лист), `supabase/tests/order_workbook.test.sql`.

## Вторая фаза: растаможка, стикеры, распределение (на том же экране)

- **Растаможка** (лист «Растаможка», только проверка): ТН ВЭД и страна происхождения сравниваются с карточкой товара
  (8-значный код поставщика и 10-значный код ЕАЭС совпадают, если один начинается с другого), количество и цена в
  инвойсе — с позицией поставки. Расхождения показываются; Nexus ничего не меняет.
- **Стикеры** (лист «Стикеры», только проверка): число индивидуальных и коробочных стикеров по товарам, размер и
  «с ЧЗ/без ЧЗ»; для каждого товара — требуется ли стикер по карточке и есть ли утверждённый штучный и коробочный
  макет (при праве `stickers.view`). Заказ стикеров по-прежнему оформляется на этапе «Стикеровка».
- **Распределение** — отдельная таблица папки «Распределение …» (её первый лист) или лист «Распределение» в
  «Вн расчетах». Столбцы «Заказ, шт» под группами: «ПРИХОД», «Продажа в <клиент>», склад (например, Алматы).
  Показываются строки с приходом и количествами по направлениям; строки, где распределено больше прихода, выделяются.
  Склады — только для сведения: перемещение оформляется после приёмки.
- **Черновики заказов клиентов**: для каждого столбца «Продажа в …» — клиент (по названию, можно выбрать), валюта
  (как в последнем заказе клиента), плановая отгрузка. Один черновик на клиента и поставку: товары и количества из
  распределения, цены — из прайса на дату заказа, склад — склад назначения поставки. Функция
  `create_distribution_orders` (миграция `202611220500_distribution_orders.sql`) создаёт отмеченные заказы одной
  транзакцией через функции заказов и запоминает связь (`shipment_distribution_orders`), поэтому повторное нажатие
  показывает уже созданный заказ. Нужно право `sales.manage`.

Проверки: `tests/shipments/order-workbook-extra.test.ts`, `supabase/tests/distribution_orders.test.sql`.
