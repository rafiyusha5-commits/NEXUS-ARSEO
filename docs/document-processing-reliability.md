# Надёжность чтения документов

Основа: `d67d3d1eccc5629bb1c1856fdcffc8730b3ccb71`, PR #52.
Это отдельная ветка, не включает изменения PR #53 и #54.

## Изменения и воспроизведение

- Раньше потерянный ответ регистрации оставлял пользователю неопределённый результат
  без сохранённого этапа. Теперь операции привязки, сканирования и импорта имеют
  квитанцию: этап, попытку, ограниченную аренду, автора, время и безопасный код.
  Успех записывается только после проверки существующего результата в БД.
- Повтор после сохранённого импорта сначала проверяет существующую квитанцию
  файла и доступ к документу, а не загружает ещё одну временную копию.
  Одновременно выполняется не более одной активной операции папки поставки.
- Старый OCR-процесс мог закончиться после выдачи новой попытки. Новая операция
  завершения принимает timestamp конкретной аренды; поздний ответ отвергается.
  Прямое выполнение старого RPC завершения закрыто. Используется прежний
  механизм begin/finish, не новая очередь; ручные подтверждения не сбрасываются.
- Истёкшая аренда отображается как требующая действия, в том числе после
  перезагрузки страницы. Процентов и обещания фонового продолжения нет.
- В сообщениях и новом диагностическом журнале нет исходных ошибок провайдера,
  SQL, содержимого файла, имён файлов или вопросов. Только UUID, этап, время и код.

## Проверки

`corepack pnpm typecheck`, `corepack pnpm lint`, `corepack pnpm test`,
`corepack pnpm build`, `corepack pnpm test:db`.

Изолированный PostgreSQL 16 запускается в CI. Локальный Docker на этой машине
недоступен; дополнительная локальная SQL-проверка в PGlite не заменяет PG16.
Новые SQL-тесты проверяют права/личные запреты, ложный успех без результата,
истечение/повтор аренды и позднее завершение OCR.
Существующий concurrent runner дополнен десятью одновременными запросами
и двумя повторами уже завершённой операции (настоящие PostgreSQL-сессии).

Подменные Drive/Storage проверяют тайм-аут до скачивания, разрыв потока,
ошибку Storage, потерянный ответ после успешной регистрации и отзыв прав.
Повтор после потерянного ответа не делает вторую загрузку или регистрацию.

`node scripts/test-processing-status-ui.mjs <absolute-playwright-module>`
проверяет реальный компонент на 1440 и 390 px, перезагрузку и две вкладки.
Это компонентный браузерный тест, не полный авторизованный сценарий Nexus.
Только синтетические данные, никакие реальные документы не проверялись.

## Применение и ограничения

1. Сначала PR #52, затем миграция `202610200300_document_processing_reliability.sql`
   и согласованная версия приложения. Старые OCR-workers после миграции не смогут
   вызвать прежний finish RPC; их нужно остановить/обновить при развёртывании владельцем.
2. Никакой worker, очередь или расписание здесь не устанавливается.
   Закрытие вкладки не обещает продолжение операции: по истечении аренды нужен повтор.
3. Частичной групповой операции нет; один файл имеет отдельный результат.
   Список показывает последние 20 операций, а не полный аудит.
4. При отзыве прав сохранение статуса ошибки также может быть запрещено:
   просроченная аренда остаётся безопасным признаком неопределённого исхода.
5. `scripts/drive-staging-cleanup-review.sql` — только read-only инвентаризация
   консервативных кандидатов. Никакая очистка не выполнялась и не планируется.
   Неизвестные/незавершённые операции и ссылки из documents/document_versions
   исключаются. Неотмеченные старые файлы требуют отдельного разбора.
   Удаление требует отдельной остановки регистраций и повторной проверки ссылок;
   небезопасная автоматическая очистка не добавлена.
6. Сетевой промежуток между последней проверкой Drive и транзакцией неизбежен;
   существующие проверки источника, версии, прав и папки сохранены.

Общие файлы с PR #53: drive-folder-actions, folder panel/view, shipment-gateway,
test-db, security_audit, shipment-drive concurrency runner.
С PR #54: source-document-actions, source-documents-panel, test-db.
При последовательном объединении нужно объединить изменения по смыслу
и повторить все проверки; независимые зелёные CI не проверяют их совместную сборку.
