# Стикеровка и маркировка

Миграция `202609272600_stickers_marking.sql` реализует этапы 14–15 процесса поставки.

## Макеты стикеров

Макет может относиться к товару и, при необходимости, к конкретному покупателю. При расчёте заказа система сначала ищет утверждённый клиентский макет, затем общий макет товара. Каждая редакция хранится отдельно. Черновик отправляется на согласование, а печать разрешена только по версии `approved`.

Файл макета сначала загружается в закрытый раздел «Документы». Поле `content` содержит тексты и переменные подстановки, например `{{product.name_ru}}`, `{{batch.number}}`, `{{batch.expiry_date}}`. При создании заказа в `render_data_snapshot` сохраняется снимок утверждённой версии и данных. Поэтому старый тираж не меняется после правки товара или публикации новой версии шаблона.

Если в поставку добавлен товар `requires_sticker = true`, а подходящего утверждённого макета нет, система создаёт маркетологу задачу в рамках этапа «Стикеровка». После утверждения общего или подходящего клиентского макета эта задача закрывается автоматически.

Количество считается как `ceil(units_to_label × (1 + reserve_pct / 100))`, затем округляется вверх до кратности минимального тиража. После приёмки сотрудник указывает фактическое нанесённое количество, брак и имя работника склада. Фактическая потребность берётся из `received_quantity`, если она уже заполнена.

## Маркировка

Заказ кодов связан с товаром, партнёром и поставкой. Реестр хранит запрошенное, полученное и нанесённое количество. Файл кодов регистрируется как закрытый документ. Значения кодов не должны попадать в Git, сообщения об ошибках или журнал приложения. Таблица `marking_codes` доступна только пользователям с `marking.manage`; экран показывает только агрегированные количества.

## Роли

- маркетолог создаёт версии макетов;
- коммерческий или логистический директор согласует макет;
- старший менеджер по логистике рассчитывает и заказывает печать и коды;
- специалист по логистике фиксирует нанесение стикеров;
- директор и администратор имеют управленческий доступ.

## Ручная проверка

1. Загрузить файл макета в «Документы».
2. Создать клиентский или общий макет, отправить версию на согласование и утвердить её.
3. Для поставки с товаром `requires_sticker = true` рассчитать заказ с запасом 3% и тиражом 100: для 480 единиц результат должен быть 495, к заказу 500.
4. Перевести заказ в «Заказан», затем «Получен», записать нанесение и брак.
5. Создать заказ маркировки для товара `requires_marking = true`, прикрепить закрытый документ кодов и записать агрегированные количества.
