# Потери по срокам годности и товар под риском

Раздел **Планирование → Потери по срокам** (`/analytics/losses`). Миграция `202611280100_loss_report.sql`, блок Г задания
`NEXUS_TASK_WAREHOUSE_MONEY_DASHBOARD.md`. Решения владельца `damirator1-afk` от 28.11.2026: приняты варианты задания по
умолчанию (Г1–Г5).

## Причина списания

Справочник `inventory_loss_reasons`:

| Код | Название |
| --- | --- |
| `expired` | Истёк срок годности |
| `damaged` | Бой, брак, повреждение |
| `count_shortage` | Недостача при пересчёте |
| `mis_sort` | Пересорт |
| `accounting_error` | Ошибка учёта |
| `other` | Прочее |

- Причина хранится в строке складского документа (`inventory_operation_lines.loss_reason_code`). Она нужна каждой строке
  списания и строке корректировки на уменьшение.
- Документ с такой строкой без причины не проводится. Проверку выполняет триггер на смене статуса «черновик → проведён»,
  поэтому её не обойти ни одной функцией проведения.
- Строку с причиной добавляет `add_inventory_loss_line`. `add_inventory_operation_line` не изменилась, ею пользуются
  перемещение и ассистент.
- В черновике причину меняет тот, кто может менять документ: `set_inventory_loss_reason`, без основания.
- Проведённая строка без причины — документы до этой миграции. Причину угадывать по тексту документа нельзя: строка
  показывается как «причина не указана».
- Администратор с правом `losses.reason_classify` может один раз указать причину такой строки с основанием от 10 до
  1000 символов. Действие записывается в `audit_log` как `inventory_loss_reason_classified`. Указанную причину
  проведённой строки изменить нельзя.

## Что считается потерей

Потери — товар, которого больше нет, по утверждённой себестоимости конкретной партии:

| Источник | Что это | Причина |
| --- | --- | --- |
| Складской документ | проведённое списание или корректировка на уменьшение; отменённый документ — не потеря | из строки |
| Списание возврата | позиция возврата клиента с решением «списать» | из возврата: `expiry` → истёк срок, `defect`/`damaged` → бой/брак, остальное → прочее |
| Прямое списание | движение `write_off` без документа (до `202609278400`) | не указана, разметить нельзя |

- **Дата потери:** дата документа; у возврата — дата решения; у прямого списания — дата движения (по Казахстану).
- **Оценка:** количество в штуках × себестоимость партии за штуку. Перевод в тенге — по официальному курсу на дату
  потери; если курса на этот день нет, берётся последний за 7 дней, как в отчёте о прибыльности.
- **Неполные данные:** нет себестоимости, упаковки или курса — строка видна с отметкой, а в сумму как ноль не входит.

**Справочно, в итог не складываются:**
- **Возвраты клиентов по сроку** — возвращённая выручка без НДС. Сам списанный возврат уже есть в потерях по
  себестоимости, поэтому сложить их значило бы посчитать одно дважды.
- **Уценка распродаж низкого срока** — недополученная выручка. Это цена прайса, сохранённая в строке заказа (блок 1б),
  минус цена программы, × отгруженное количество, без НДС. Строка без цены прайса отмечена «нет цены прайса в строке
  заказа».

**Доля потерь** — от себестоимости проданного за тот же период: утверждённая себестоимость продаж из отчёта о прибыльности.

## Отчёты

| Функция | Что даёт |
| --- | --- |
| `loss_report(group, from, to)` | потери периода по причинам, товарам, брендам, складам, поставкам или месяцам; итог, доля, справочные колонки |
| `loss_report_lines(from, to)` | строки для выгрузки XLSX |
| `loss_risk(group)` | товар под риском сейчас по сроку, складам, брендам или поставщикам; до 500 строк партий |
| `loss_trend(months)` | потери по месяцам и причинам за 1–36 месяцев с долей от себестоимости продаж |
| `unclassified_loss_lines(limit)` | проведённые строки без причины — для разметки администратором |

- **Под риском:** остатки, срок годности которых истёк или истекает в ближайшие 90 дней. Группы: «срок истёк»,
  «до 30 дней», «31–90 дней». Оценка — себестоимость по официальному курсу на сегодня.
- **План остатка:**
  - «в распродаже низкого срока» — строка утверждённой или заказанной программы ссылается на этот остаток;
  - «в резерве под заказ» или «частично в резерве»;
  - «нет плана продажи».
- **Бренд:** бренд из справочника; если карточка товара не совпадает со справочником — текст карточки; если бренда нет —
  «Без бренда».
- **Поставка партии:** первая поставка партии (как у себестоимости по первому приходу); для разреза потерь этого достаточно.

## Права

| Право | Что даёт |
| --- | --- |
| `reports.view` + `inventory.view` | отчёты, количества |
| + `prices.purchase.view` | суммы. Без него база отдаёт все суммы и долю пустыми — и на экране, и в выгрузке, и ассистенту |
| `losses.reason_classify` | причина проведённого списания без причины; выдано роли `administrator`. Отдельный модуль `losses`: старые миграции при повторном применении раздают роли права целого модуля |

Ассистент читает отчёты `losses` и `loss_risk` теми же функциями и с теми же правами.

## Проверка

`supabase/tests/loss_report.test.sql` — синтетический сценарий с ручным расчётом при курсе EUR → KZT 500:
- списания с разными причинами, уменьшение и увеличение остатка;
- документ, проведённый без причины, и его разметка;
- отменённое списание, партия без себестоимости, прямое движение;
- списанный возврат, возврат по сроку, уценка распродажи;
- товар под риском во всех трёх группах;
- права без сумм и без отчётов.

Проверка поломкой: если сложить возвраты в итог, тест падает на сумме 85 000; если убрать проверку причины при
проведении, тест падает на ожидаемом отказе.
