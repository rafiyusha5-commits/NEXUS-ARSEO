# Контекст источника: операция и автомобиль

Основа: `d67d3d1eccc5629bb1c1856fdcffc8730b3ccb71`, зависимость #52/#51.
Модель не расширяется до графа транспортных участков: операция — существующая
поставка (`import/export/domestic_transfer`), автомобиль — `shipment_transports`,
связь исходника — `document_links` и `shipment_source_extractions.shipment_transport_id`.
Продажа через заказ не становится импортной перевозкой по названию файла/папки.

## Воспроизведённые дефекты

1. `assign_source_extraction_transport` не проверял актуальность документа.
   Отвязать документ, вызвать старый RPC: автомобиль извлечения менялся.
   `supabase/tests/before/202610200200_document_transport_context.sql`
   подтверждает поведение до исправления; после — отказ обеих сигнатур.
2. `mergeConfirmedSources` считал адреса загрузки/выгрузки и страны маршрута
   общими для поставки. При двух машинах адрес документа машины B попадал
   в CMR машины A. Новый TS-тест фактически падал на основе, теперь проходит.
   Общий маршрут документа всей поставки остаётся общим, как прежде;
   это отдельно покрыто регрессией, новое бизнес-правило не вводится.
3. Генерация читала подтверждения без проверки текущей версии/действующей
   связи. Теперь используется существующий currentCommoditySource с более
   строгой проверкой конкретной машины; неполная выборка блокирует сборку.
4. Метки происхождения полей считались по всем автомобилям, хотя значения
   фильтровались. Теперь значения и метки используют один scopeConfirmedSources.
   Строки инвойса, явно относящегося к другой машине, не участвуют.

## Итог

Существующий RPC назначения расширен причиной и теми же блокировками/проверками
текущего источника, что в подтверждении. Подтверждённые, устаревшие и ещё
распознаваемые источники не перепривязываются. Автоматического снятия подтверждений
нет. История содержит старый/новый автомобиль, причину, сотрудника и время;
повтор неизменного назначения не добавляет запись. Прежние двуаргументные вызовы
сохранены для контролируемого отказа: без явной причины операция запрещена.
Новый интерфейс требует осмысленную причину сотрудника.

История и извлечения учитывают видимость ценосодержащих документов. Панель
показывает операцию и машину, источники без машины требуют ручного разбора.
Никакой массовой перепривязки. «Сверка» не использует связь с машиной B
как разрешение проверять извлечение, назначенное машине A; прежнее скрытие
деталей недоступных документов в выдаче агента сохранено.

## Ограничения / применение

Миграция `202610200200_document_transport_context.sql` после #52.
Добавляет историю и расширяет существующий RPC; права ролей/service_role
не расширяет. Нет очистки, массового изменения источников или расписания.
Объединение с PR сопоставления не требуется; общий файл `scripts/test-db.sh`.

Внутри одной поставки нет отдельной сущности участка маршрута и неизменяемого
снимка тягача на момент подтверждения. Если одна запись автомобиля используется
для последовательных участков, автоматически определить, какой участок описан
документом, нельзя. Интерфейс обозначает эту границу; история старых подтверждений
не переносится и не переписывается. Дальнейшее моделирование участков требует
отдельного бизнес-решения. Намеренно вручную связанный с неверной операцией
документ по номеру машины/языку распознать как ошибку достоверно невозможно.
Оригинал и перевод остаются отдельными документами; их смысловая идентичность
не устанавливается.

Реальные документы, Drive, OCR и базы владельца не использовались.
Локальный SQL smoke — WASM; PostgreSQL16 проверяется в одноразовом CI.
Локальный Windows build прошёл; Linux build оценивается отдельно по CI.

Общие файлы: `rules.ts` (разбор текста не менялся, только область применения
подтверждённых полей), `generation-assembly.ts`, `generation-service.ts`,
`source-document-actions.ts`, `shipment-source-documents-panel.tsx`,
`globals.css`, `test-db.sh`. PR надёжности может пересечься с actions/panel.
