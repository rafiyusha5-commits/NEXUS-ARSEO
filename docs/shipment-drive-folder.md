# Папка Drive для поставки

На вкладке «Документы» поставки: «Папка Google Drive» → ссылка на папку →
«Привязать папку» → «Проверить папку». Проверка включает вложенные папки.
Разрешены два согласованных владельцем источника: архив «2026»
`1ffI_2N0F9Gy3N8r5XgNRv-hipmCl1ele` и «Будущие заказы (ARSEO)»
`1H0DGNKrBgsIGdUvWqN2BHajjdgXmvvCC` (добавлен 02.11.2026).
Привязывается папка отдельной поставки, а не целый источник.
Общий архив ассистента не меняется. Нужен доступ Reader к источнику и его папкам.

Для нового файла сотрудник выбирает тип, отмечает согласие и нажимает
«Загрузить для проверки». Если такой файл уже есть в Nexus, добавляется связь
с существующим документом. Распознавание, ручная проверка и перенос значений
в поставку выполняются отдельно существующими действиями.

Проверка папки не изменяет документы, распознавание, ручные подтверждения,
товарные строки, расходы или склад. Изменённый исходник получает предупреждение;
ранее импортированный документ не заменяется. Для замены нужно отдельно сравнить
документы и согласовать штатную загрузку новой версии. Удаление файла на Drive
помечается в списке, но не удаляет сохранённый документ Nexus. Замена привязанной
папки в этой версии запрещена; повтор той же привязки безопасен.

## Доступ и целостность

- Только Drive `GET` и scope `drive.readonly`. OAuth POST используется исключительно
  для получения токена. Ярлыки не обходятся, внешние URL не запрашиваются.
- Корни заданы сервером, не формой или моделью. После первой успешной проверки
  клиент закреплён за одним корнем на всю операцию; смена дерева в ходе операции
  отклоняется, даже если второе дерево тоже разрешено.
  Цепочка родителей проверяется при привязке, обходе,
  перед/после скачивания и перед регистрацией. Сверяется версия Drive `version`.
- Сессия сотрудника, существующий серверный `DRIVE_CATALOG_GATEWAY_SECRET` и RLS.
  Нужны `shipments.view`, `shipments.update`, `documents.view`,
  `documents.drive.view`, `prices.purchase.view`; для загрузки также
  `documents.create` и `documents.update`. Персональный запрет действует.
  Новые права ролям и service_role не выдаются.
- Одна привязка на поставку, одна запись на ID источника. Регистрация документа,
  привязка и отметка импорта выполняются одной транзакцией. Строковые блокировки
  и блокировка по SHA-256 защищают параллельные импорты через этот механизм.
- Совпадение SHA-256 с существующим доступным документом повторно использует
  текущую неархивную версию. Несовпадение выбранного типа или совпадение со старой
  версией требуют ручной проверки. Эта функция не меняет правила обычной ручной
  загрузки документов; конкурентная загрузка вне данного механизма не разделяет
  его блокировку SHA-256.
- При неопределённом результате сетевого запроса приватный временный объект
  Nexus не удаляется: он мог уже зарегистрироваться. Повтор проверяет запись
  импорта. Остаточные незарегистрированные объекты требуют отдельной уборки;
  очистка Google Drive не выполняется никогда.

## Ограничения и внедрение

Проверка по кнопке, без фонового расписания. До 500 файлов, 50 страниц API и
90 секунд на обход. Не более трёх страниц папок читаются одновременно; каждая
сохраняет полную проверку родителей до и после чтения. Ошибка отменяет оставшиеся
запросы. Превышение/ошибка не публикуют частичный результат как полный.
Файлы до 4 МБ — действующий лимит хранилища Nexus. Google Docs/Sheets/Slides
читаются через GET export; оригиналы неизменны. Идентичный перевод не определяется
по смыслу: разные байты остаются отдельными документами, их назначение проверяет
сотрудник. Смена файлов в Drive и транзакция Nexus не атомарны; остаётся сетевое
окно после последней проверки, но подтверждённые значения не заменяются.

Миграция `202610190100_shipment_drive_folders.sql` создаёт пустые таблицы привязок
и источников. Не обходит существующие поставки, не импортирует файлы и не меняет
бизнес-данные. Нужны настроенный серверный шлюз и доступ Reader к архиву.
После внедрения сначала привязать одну поставку, проверить список и вручную
загрузить один документ. Повторить проверку и загрузку: документ должен остаться один.

Проверки: `tests/shipment-drive-folder.test.ts`,
`supabase/tests/shipment_drive_folders.test.sql`, общий набор прав и индексов.
Тесты используют только синтетические данные, не документы HS-39.
`tests/shipment-drive-roots.test.ts` проверяет оба источника, отказ внешнему дереву,
ярлыкам, подложной цепочке, отозванному доступу и перемещению во время скачивания.
Добавление второго источника и ограниченный параллельный обход не требуют миграции.
