# Роли и права доступа Nexus-ARSEO

Статус документа: черновик. Матрица задаёт **права по умолчанию**. Администратор может менять их для роли или для отдельного сотрудника (см. «Как администратор ограничивает доступ»).

Техническая реализация — сущности `roles`, `permissions`, `role_permissions`, `employee_roles` (см. [`docs/data-model.md`](./data-model.md)).

## Обозначения

| Код | Значение | `role_permissions.access_level` | Пояснение |
|---|---|---|---|
| **Р** | разрешено | `allowed` | действие доступно без дополнительных условий |
| **З** | запрещено | `denied` | действие недоступно |
| **О** | ограничено | `restricted` | доступно в пределах, описанных под таблицей раздела (например, только свои записи или только свой склад) |
| **ОР** | по отдельному разрешению | `by_grant` | недоступно, пока администратор или директор не выдаст разрешение конкретному сотруднику |
| — | не применимо | — | у раздела нет такого действия |

## Роли

| Сокращение | Роль | Системный код |
|---|---|---|
| Дир | Директор | `director` |
| ИД | Исполнительный директор | `executive_director` |
| КД | Коммерческий директор | `commercial_director` |
| ДЛ | Директор по логистике | `logistics_director` |
| СМЛ | Старший менеджер по логистике | `senior_logistics_manager` |
| МЛ | Менеджер или специалист по логистике | `logistics_manager` |
| Бух | Бухгалтер | `accountant` |
| Марк | Маркетолог | `marketer` |
| Адм | Администратор системы | `system_admin` |

Администратор пилота — Рафия. У неё две роли: «Старший менеджер по логистике» и «Администратор системы» (две записи `employee_roles`). Права СМЛ в таблицах ниже описывают только логистическую роль, без административных прав.

## Действия

| Столбец | Действие | `permissions.action` |
|---|---|---|
| Просм. | просмотр | `view` |
| Созд. | создание | `create` |
| Изм. | изменение | `edit` |
| Удал. | удаление или архивирование | `delete_archive` |
| Согл. | согласование | `approve` |
| Эксп. | экспорт | `export` |
| Загр. | загрузка файлов | `upload` |
| Статус | изменение статуса | `change_status` |
| Права | управление правами на раздел | `manage_access` |

## Общие правила

1. **Просмотр по умолчанию.** Сотрудники видят основные данные: контрагентов, товары, склады, остатки, поставки, документы, отчёты. Финансы, себестоимость и дебиторская задолженность доступны не всем.
2. **Ключевые справочники** (клиенты, поставщики, товары, склады, шаблоны, роли, системные настройки) создают и изменяют директор и администратор. Остальным ролям — **ОР**.
3. **Удаление = архивирование.** Физическое удаление бизнес-данных не предусмотрено. Движения, версии документов, курсы и журнал действий не архивируются и не удаляются — ошибки исправляются сторнирующей записью.
4. **Управление правами** на любой раздел: Директор и Администратор — **Р**, Исполнительный директор — **О** (может менять права операционных ролей, но не Директора и Администратора), остальные — **З**.
5. **Разделение обязанностей.** Администратор управляет доступом, но не видит финансовые данные без отдельного разрешения.

## Как администратор ограничивает доступ

Администратор (и Директор) могут:

1. **Изменить право для роли** — поменять `role_permissions.access_level` любой ячейки матрицы (например, запретить Маркетологу просмотр остатков).
2. **Ограничить отдельного сотрудника** — добавить запрет (`deny`) в `employee_roles.permissions_override`. Запрет действует, даже если роль даёт доступ.
3. **Выдать отдельное разрешение** — добавить разрешение (`allow`) в `permissions_override`. Так открываются все ячейки **ОР**. Разрешение может быть временным (`expires_at`).
4. **Отключить доступ полностью** — `users.is_active = false`.

Каждое изменение прав записывается в `audit_log` с состоянием до и после.

### Как вычисляется итоговое право

1. Есть `deny` у сотрудника → **запрещено**.
2. Есть `allow` у сотрудника → **разрешено** (это и есть «по отдельному разрешению»).
3. Иначе берётся самый широкий уровень среди активных ролей сотрудника: Р > О > З. Ячейка **ОР** без выданного разрешения равна **З**.

### Защитные правила

- Нельзя отключить последнего активного Администратора и последнего активного Директора.
- Права Директора может менять только сам Директор — **«Требует подтверждения ARSEO»**.
- Администратор не выдаёт себе доступ к финансам сам: разрешение выдаёт Директор.
- Журнал действий не меняется и не удаляется никем.
