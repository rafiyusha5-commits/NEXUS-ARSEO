# Рабочий день Казахстана

Находка Н10 аудита 13.10.2026. Миграции `202609278100_order_recovery_business_date.sql` (продажи и отгрузка заказа) и `202609278300_kazakhstan_business_date.sql` (всё остальное).

База Supabase работает в UTC. Казахстан живёт в UTC+5, поэтому с 00:00 до 05:00 по местному времени «сегодня» по UTC — ещё вчера. Раньше в эти часы база:
- ставила вчерашние фактические даты прибытия;
- в новогоднюю ночь ставила прошлый год в номерах;
- считала годной партию, срок которой истёк вчера: в FEFO-выдаче, отгрузке заказа и остатках;
- отклоняла курс, датированный сегодняшним днём.

## Правило

- **База, новый код.** Рабочая дата — `private.business_today()` (из 8100) или явное `(now() at time zone 'Asia/Almaty')::date`. Явное `at time zone 'UTC'` для рабочих дат запрещено.
- **База, функции с `current_date`.** Каждая функция, которая берёт текущую дату через `current_date`, `now()::date` или `localtimestamp`, работает с настройкой `set timezone to 'Asia/Almaty'`. Миграция 8300 проставила её всем таким функциям, не меняя их тела. Новую или переопределённую функцию с `current_date` нужно объявлять так же:

  ```sql
  create or replace function public.example() returns void
  language plpgsql security definer set search_path = '' set timezone to 'Asia/Almaty' as $$ ... $$;
  ```

  В представлениях и значениях по умолчанию дата пишется явно: `(now() at time zone 'Asia/Almaty')::date`.
- **Проверка.** `supabase/tests/business_date.test.sql` падает и называет функцию, если она читает текущую дату без этой настройки. Он же проверяет поведение в двух крайних часовых поясах сессии (UTC−12 и UTC+14): в любой момент хотя бы один из них живёт в другом дне, чем Казахстан.
- **Тесты.** SQL-тесты работают в поясе `Asia/Almaty` (`PGOPTIONS` в `scripts/test-db.sh`). Их собственное `current_date` — тот же рабочий день, что у функций, в любое время суток.
- **Приложение.** Дата «сегодня» для полей ввода и сравнений — `businessToday()` из `src/lib/dates/business-day.ts`, а не `new Date().toISOString().slice(0, 10)` (это дата по UTC).

Казахстан с 1 марта 2024 года живёт в одном поясе UTC+5. Помощники агентов, где указаны `Asia/Qyzylorda` или `Asia/Aqtobe`, дают тот же день.
