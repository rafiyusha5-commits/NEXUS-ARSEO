# Инвентаризация (блок А)

Миграция `202611280300_inventory_counts.sql`, экран «Склад → Инвентаризация» (`/inventory/counts`). Решения владельца
`damirator1-afk` от 28.11.2026: приняты все решения задания по умолчанию (А1–А6). Основана на справочнике причин
списания блока Г ([losses.md](losses.md)).

## Жизненный цикл

**Черновик → подсчёт → повторный подсчёт → на утверждении → проведена**. Отменить можно на любом шаге.

1. **Черновик.** Склад, вид и режим:
   - вид — весь склад или часть: места, зоны целиком, остатки без зоны, товары. Если заданы и места, и товары, действуют оба условия;
   - режим — слепой (по умолчанию) или открытый.
2. **Старт.**
   - Запоминается учётный снимок: каждая строка остатка в составе пересчёта — партия, место, единица, количество, резерв.
   - С этого момента количество на руках по считаемым местам не меняется, пока пересчёт не проведён или не отменён (А3). Под запрет попадают отгрузка, перемещение, списание, приёмка на это место и прямое изменение. Сообщение называет номер пересчёта и место.
   - Остальные места склада работают как обычно; резервы заказов не блокируются.
   - На складе одновременно открыт только один пересчёт.
3. **Подсчёт.**
   - Запись: место, товар, партия, единица, количество, кто и когда.
   - Упаковки — только те, что заданы у товара (`uom_pieces`).
   - Товар без читаемой партии записывается как «партия не определена».
   - Записи одной позиции складываются: двое могут считать одно место, ничего не теряется.
   - Ошибку исправляют новой записью со ссылкой на прежнюю. Прежняя остаётся в истории и больше не учитывается; правка и удаление записей запрещены.
   - Запись передаёт номер тура. Запись первого тура, отправленная в момент завершения тура, отклоняется и не становится повторным подсчётом.
4. **Завершение подсчёта.**
   - Строятся строки «учёт против подсчёта» по месту, партии и единице. Место без записей считается пустым.
   - Строки с разницей больше допуска и все «партия не определена» уходят на повторный подсчёт (А4). Допуск в штуках задаёт администратор, по умолчанию 0; значение берётся на момент старта пересчёта.
   - Повторно считает другой сотрудник — не тот, кто считал эту позицию в первый раз. Итог строки — повторный подсчёт.
5. **Разбор** (право `inventory.count.approve`, А5).
   - У каждой недостачи — причина из справочника потерь.
   - Недостачу можно связать с излишком того же пересчёта как пересорт: связь видна с обеих сторон, причина по умолчанию — «пересорт». Для той же партии на другом месте — «ошибка учёта».
   - Излишек партии, которая по учёту лежит на другом месте пересчёта, помечен «другое место».
   - Для «партия не определена» — выбрать партию товара или «не учитывать».
   - Если после списания остаток места станет меньше текущего резерва заказов, строка не проводится: экран называет заказы, резерв снимают или заменяют в заказе.
6. **Проведение.**
   - Один документ корректировки ([складские документы](inventory-operation-documents.md)) со строкой на каждую разницу: уменьшения — с причиной, увеличения — без неё. Документ проводится его собственной функцией, со всеми её проверками и правами (`inventory.control`).
   - Для товара, найденного там, где у партии нет строки остатка, открывается пустая строка остатка; количество на неё кладёт корректировка.
   - До проведения остатки не меняются.
   - Предпросмотр с устаревшими данными (решения, остатки или резервы изменились после открытия разбора) отклоняется.
   - Повторное проведение невозможно.
7. **Отмена.**
   - До проведения остатки не менялись, блокировка снимается.
   - Проведённую инвентаризацию отменяет утверждающий: документ корректировки отменяется его собственным сторно. Если товар уже использован, сторно откажет.

## Слепой пересчёт (А2)

- Функции подсчёта (`inventory_count_sheet`, `inventory_count_catalog`) и бланк PDF не отдают учётного количества.
- Бланк слепого пересчёта — пустые строки по каждому месту, без списка того, что там лежит по учёту.
- Разбор открывается только после завершения подсчёта и только утверждающему.
- Снимок и строки закрыты RLS.
- Ограничение: сотрудник с правом «Остатки: просмотр» по-прежнему видит остатки на экране «Остатки и партии». Для строгого слепого пересчёта считающим можно не давать это право — для подсчёта оно не нужно.

## Деньги (А6)

Разница в тенге — по себестоимости партии (`unit_landed_cost` в её валюте, пересчёт по официальному курсу на сегодня).
Показывается только с правом `prices.purchase.view`: без него сумм нет ни на экране, ни в отчёте, ни в выгрузке. Партия
без себестоимости или без курса — пометка «нет себестоимости», а не ноль.

## Права

| Право | Что даёт | По умолчанию |
| --- | --- | --- |
| `inventory.count.manage` | создать, задать состав, начать, завершить тур, отменить до проведения | администратор, директора, логисты |
| `inventory.count.record` | вносить подсчёт | те же роли |
| `inventory.count.approve` | разбор, проведение, отмена проведённой | администратор, директор, исполнительный директор, директор по логистике |
| `inventory.count.settings` | допуск расхождения | администратор |

Видеть журнал может сотрудник с любым из этих прав или с «Остатки: просмотр». Проведение дополнительно требует права
корректировки остатков (`inventory.control`) — его проверяет документ корректировки.

## Бланки, отчёт, ассистент

- Бланк PDF (`/inventory/counts/{id}/sheet`): по местам; в повторном подсчёте — список позиций и кто не должен их считать.
- Отчёт XLSX (`/inventory/counts/{id}/export`): итоги, строки, по причинам и по местам. Суммы в деньгах — только с правом.
- Ассистент, только чтение: `inventory_counts` — журнал пересчётов. Разбор одного пересчёта ассистенту не добавлен: для этого
  нужен новый параметр в списке разрешённых параметров записи хода (`private.agent_clean_tools`) — отдельное изменение.

## Функции

| Функция | Что делает |
| --- | --- |
| `create_inventory_count`, `set_inventory_count_scope`, `start_inventory_count` | черновик, состав, старт со снимком |
| `record_inventory_count(пересчёт, тур, место, товар, партия, единица, количество, примечание, исправляет)` | запись подсчёта |
| `finish_inventory_count_round` | конец тура: строки и повторный подсчёт, затем разбор |
| `inventory_count_sheet`, `inventory_count_catalog` | что видит считающий; товары и партии без количества |
| `inventory_count_review` | учёт против подсчёта, решения, проблемы, суммы по причинам и местам, отпечаток предпросмотра |
| `set_inventory_count_decision`, `pair_inventory_count_lines` | причина, партия, пересорт |
| `post_inventory_count(пересчёт, отпечаток)`, `cancel_inventory_count` | проведение и отмена |
| `inventory_count_list`, `set_inventory_count_tolerance` | журнал, допуск |

Блокировка — триггер `inventory_balances_count_lock` на изменение количества на руках. Проведение пересчёта
проходит через него по признаку своей транзакции.

## Проверки

**`supabase/tests/inventory_counts.test.sql`** — сценарий «3 места, 5 партий»:
- недостача, пересорт, партия на другом месте, партия не определена;
- двое считают одно место, исправление;
- повторный подсчёт другим сотрудником;
- блокировка мест (прямо, документом списания, новой строкой остатка), свободное место вне состава;
- слепой режим: ни в бланке, ни в функциях;
- резерв заказа мешает списанию, устаревший предпросмотр;
- проведение ровно на утверждённое, повторное проведение, сторно;
- права, деньги без закупочных цен, допуск.

**Проверки поломкой:**
- если проведение меняет остаток мимо документа корректировки, проверка «остаток менялся только документом» падает;
- без триггера блокировки падает проверка блокировки;
- если слепой бланк отдаёт учёт, падает проверка бланка.

**`scripts/test-inventory-count-concurrency.mjs`:**
- два одновременных исправления одной записи — проходит одно;
- записи, отправленные до завершения тура, учтены все; отправленные после — отклонены и не сохранены.
