# Прибыльность (блок 3)

Миграция `202611170500_profitability.sql`, экран «Аналитика → Прибыльность» (`/analytics/profitability`),
выгрузка строк в XLSX. Решения владельца `damirator1-afk` от 16–17.11.2026, открытые вопросы — по умолчанию.

## Что считается

Строка отчёта — одна отгруженная партия строки заказа (движение `issue` с `sale_item_id`) или одна
возвращённая партия (`customer_return_items` неотменённого возврата).

- **Только отгруженное.** Резерв и подтверждение в выручку не входят.
- **Дата строки.** Для продажи — день отгрузки по времени Казахстана; у исторической продажи — её
  дата отгрузки. Для возврата — день приёмки возврата. Возвраты уменьшают выручку и себестоимость
  периода возврата и показаны отдельно.
- **Выручка** = количество × цена строки заказа, в валюте заказа. Без НДС — по ставке из
  `vat_rates`; рядом отдельной колонкой показана выручка с НДС. Как определяется, включает ли цена НДС:
  1. по снимку цены строки (блок 1б);
  2. если снимка нет — по виду цены клиента на дату заказа;
  3. если нет и вида цены — по стране клиента: Казахстан с НДС, экспорт без.
- **Себестоимость** = количество из конкретной партии × себестоимость этой партии, без усреднения по
  товару. Утверждённая себестоимость берётся как утверждена. Если у партии её нет, но есть черновой
  расчёт её первого прихода, строка помечается «предварительно».
- **Пересчёт в тенге** — по официальному курсу (`exchange_rates.source = 'official'`) на дату
  отгрузки. Если курса на эту дату нет, берётся последний официальный за 7 дней, как в блоке 1 (дата
  курса видна в выгрузке). Это делает функция `private.official_conversion`: прямая пара, обратная
  или через тенге. `private.finance_rate` (Н14) не используется и не меняется.
  Находка Н1 аудита 18.11 («по сегодняшнему курсу») не подтвердилась: тест
  `profitability_cost_rate_date.test.sql` — отгрузка 30 дней назад, курс того дня 500, сегодня 600 —
  себестоимость пересчитана по 500.
- Маржа на штуку совпадает с формулой блока 1Б (`private.batch_margin`) — это проверяется тестом.

## Отметки строк

| Отметка | Когда |
| --- | --- |
| утверждено | цена, утверждённая себестоимость, курсы и ставка НДС есть |
| предварительно | себестоимость только из чернового расчёта |
| нет цены продажи | у строки заказа нет цены |
| нет себестоимости | ни утверждённой, ни черновой себестоимости |
| нет курса | нет официального курса за 7 дней |
| нет ставки НДС | цена с НДС, а ставка не задана |
| нет упаковки | единицу нельзя пересчитать в штуки |

Партии с себестоимостью по прежнему правилу (`cost_basis = 'source_item'`, Н6) дополнительно помечены.

**Как неполные строки учитываются в итогах:**
- Прибыль и маржа считаются только по строкам «утверждено».
- Выручка учитывает все строки, где её можно перевести в тенге.
- Доля выручки с полными данными показана отдельно.
- Неполные строки видны и в маржу как ноль не входят.

## Отчёты

`profitability_report(разрез, с, по)` — разрезы `shipment`, `product`, `customer`. Итог прибыли
одинаков во всех трёх разрезах: в разрезах по товару и клиенту строка входит ровно в одну группу, по поставке
она может делиться (см. ниже), но доли в сумме дают целое.

**Что показано по каждой группе:**
- продажи без НДС и с НДС;
- возвраты;
- выручка с полными данными;
- себестоимость, валовая прибыль, маржа;
- полнота данных;
- отметки строк.

Строка относится к поставке прихода партии. Если одна партия пришла несколькими поставками (вторая приёмка
того же номера партии и срока добавляется к существующей партии), то с 21.11.2026 (миграция
`202611210300_profitability_shipment_shares.sql`, находка Н3, решение владельца `damirator1-afk`) строка делится
между поставками пропорционально принятым штукам: выручка, себестоимость, проданные и непроданные штуки. Раньше
вся партия относилась к первой поставке. Себестоимость партии и так средневзвешенная по приходам, поэтому маржа у
долей одинаковая. В выгрузке строки у такой партии перечислены все поставки с долями. По поставке дополнительно
показан непроданный остаток в штуках. Строки для проверки и выгрузки возвращает `profitability_lines(с, по)`.

## Доступ

Нужны `reports.view` и `prices.purchase.view` одновременно. Клиент портала не сотрудник и доступа не
получает. Без прав функции отказывают, а не возвращают пустые цифры.

## Производительность

На 50 000 движений отгрузки (2 500 заказов, 10 000 строк, 200 партий) отчёт строится примерно за 1 с,
выгрузка строк — примерно за 2,4 с (PostgreSQL 16, локально).

**Что для этого сделано:**
- признак НДС, себестоимость партии, упаковка и курсы считаются один раз на строку заказа, партию,
  пару «товар + единица» и пару «валюта + день», а не на каждое движение;
- JIT в функциях отчёта выключен: оценки строк у функций завышены, и компиляция стоила дороже всего
  отчёта;
- добавлены частичные индексы по дате движений отгрузки и дате возвратов.

## Не входит

- Расходы, отнесённые на клиента (`attributed_customer_id`, промо), — вторым шагом, отдельной строкой.
- Чистая прибыль с накладными расходами, план-факт, прогноз.
