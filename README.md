# Nexus-ARSEO

Закрытая корпоративная система ТОО ARSEO для управления импортом, экспортом, логистикой, складом, документами и аналитикой.

## Пилот

Первый пилот строится на реальном проекте RVI Fazer (Leib4-x–Leib7-x). Рабочие документы и персональные данные не хранятся в GitHub.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

Приложение откроется по адресу `http://localhost:3000`.

## Проверки

```bash
pnpm lint
pnpm build
```

## Supabase

Приложение использует Supabase для PostgreSQL, авторизации и будущего объектного хранилища документов.

1. Создайте `.env.local` по образцу `.env.example`.
2. Добавьте URL проекта и publishable key из Supabase.
3. Примените SQL-файлы из `supabase/migrations`.
4. Создайте первого сотрудника через Supabase Auth и назначьте ему роль администратора через SQL Editor.
5. Примените миграцию фазы 0, после чего пользователями и правами можно управлять из интерфейса Nexus.

Ключ `SUPABASE_SECRET_KEY` нужен только серверу для отправки приглашений сотрудникам. Его нельзя добавлять в клиентский код или GitHub. Старый `SUPABASE_SERVICE_ROLE_KEY` поддерживается как резервный вариант.

Без переменных Supabase проект запускается в демо-режиме, чтобы интерфейс можно было разрабатывать до подключения облачной базы.

## Документы

Модуль «Документы» хранит файлы в приватном Storage bucket `nexus-documents` (создаётся миграцией `202609271001_document_management.sql`), выдаёт их по временным ссылкам и не использует секретный ключ Supabase. Максимальный размер файла — 4 МБ. Применение миграции, проверка bucket, права и откат описаны в [`docs/documents-module.md`](docs/documents-module.md).

Шаблоны документов (с версиями файлов) и карты ввода/вывода товара описаны в [`docs/templates-listing-cards.md`](docs/templates-listing-cards.md); миграция `202609271700_document_templates_listing_cards.sql` применяется после всех предыдущих.

Сканы и фотографии исходных документов можно распознавать собственным OCR-сервисом. Docker-образ,
правила безопасного развёртывания и подключение к Nexus описаны в [`services/ocr/README.md`](services/ocr/README.md).

## Импорт справочника

Контрагенты, товары, идентификаторы (GTIN, штрихкоды, артикулы поставщиков) и упаковка загружаются на экране «Товары» → «Импорт справочника» из JSON-пакета или таблиц CSV/XLSX. Сначала выполняется проверка без записи с отчётом по каждой строке, затем весь пакет записывается одной транзакцией. Повторная загрузка не создаёт дублей. Цены и договорные условия в этот импорт не входят. Нужны права «Товары: создание» и «Товары: изменение». Формат файла, правила сопоставления и ограничения описаны в [`docs/reference-import.md`](docs/reference-import.md). Миграция — `202609271900_reference_data_import.sql`.

Исходные Excel-файлы с ценами и условиями и извлечённые из них данные в Git не добавляются (папка `local-imports/` исключена).

## Задачи и уведомления

Страница «Задачи» (`/tasks`) показывает задачи поставок с фильтрами «Мои», «Все», «Открытые», «Просроченные», «Завершённые» и фильтром по поставке. Исполнитель начинает и завершает свою задачу, руководитель (право «Задачи: управление») переназначает её и меняет срок. Страница «Уведомления» (`/notifications`) собирает назначения, приближение и просрочку сроков, блокировки этапов, запросы и решения согласований; число непрочитанных видно в боковой панели. Миграция `202609272200_shipment_tasks_notifications.sql`, права, события и ручная проверка описаны в [`docs/tasks-notifications.md`](docs/tasks-notifications.md).

Приёмка прибывшего автомобиля выполняется из карточки поставки одной операцией: система фиксирует принятое, повреждённое, недостачу или излишек, создаёт партии, складской остаток и движения, переводит автомобиль в статус «Разгружен» и завершает этапы приёмки. Повторная приёмка исключена. Подробности — в [docs/shipment-receiving.md](docs/shipment-receiving.md).

## Безопасность базы данных

Аудит RLS, функций `SECURITY DEFINER`, прямых изменений в обход RPC и косвенных утечек (уведомления, журнал, согласования) описан в [`docs/security-audit.md`](docs/security-audit.md): найденные проблемы, исправления миграцией `202609272300_database_security_hardening.sql`, изменения поведения, остаточные риски и матрица «модуль → таблицы/RPC → право → RLS → роли → проверенный запрет». `pnpm test:db` сначала воспроизводит каждый найденный обход на схеме до исправления, затем проверяет, что он закрыт.

Независимая проверка всего проекта на 12.10.2026 — в [`docs/audit-2026-10-12.md`](docs/audit-2026-10-12.md): уязвимости зависимостей, риски Telegram-канала и ассистента, отсутствие непрерывной интеграции, резервных копий и мониторинга, а также перечень того, что надёжно и переделки не требует.
